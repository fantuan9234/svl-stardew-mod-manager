## 根本原因分析

### 主要问题：Tauri 应用浏览器测试限制

SVL 是基于 Tauri 框架构建的桌面应用，具有以下特点：

1. **依赖 Tauri API**: 应用启动时需要调用 `@tauri-apps/api` 获取系统信息
2. **文件系统访问**: 直接读写本地文件（MOD、档案、存档等）
3. **Rust 后端命令**: 通过 `invoke()` 调用 Rust 实现的命令
4. **窗口管理**: 使用 Tauri 窗口 API 控制应用窗口

**Playwright 浏览器测试的局限性**:
- 无法完全模拟 Tauri 运行时环境
- Mock 脚本只能覆盖部分 API
- 文件系统操作无法在浏览器中执行
- Rust 后端命令无法在浏览器中调用

### 测试架构建议

为了进行有效的全功能回归测试，建议采用以下方案：

#### 方案 A: Tauri 桌面测试（推荐）
```bash
# 使用 Tauri 测试命令
cargo tauri test
```
- 优点：完整测试 Tauri 应用
- 缺点：需要编译 Rust 代码，测试速度较慢

#### 方案 B: 混合测试策略
1. **单元测试**: 测试 React 组件逻辑（Jest/Vitest）
2. **集成测试**: 测试 Rust 后端命令（cargo test）
3. **E2E 测试**: 使用 Tauri 的测试工具进行桌面测试
4. **UI 测试**: 使用 Playwright 测试静态 UI 元素

#### 方案 C: 改进的 Playwright 测试
增强 Tauri Mock 脚本，覆盖更多 API：
- 完整的文件系统模拟
- 所有 Rust 命令的 mock 实现
- 窗口事件模拟
- 更真实的测试数据
